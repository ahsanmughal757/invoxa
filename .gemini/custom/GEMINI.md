# GEMINI.md (Strict Enforcement)

## 🎯 Purpose
All code generated by Gemini must:
1. Treat the **database schema as the single source of truth**.  
2. Auto-generate **types, validation, and UI forms** from the schema.  
3. Prevent all schema mismatches, invalid UUIDs, missing attributes, or silent failures.  
4. Always scaffold code using the rules below.  

---

## 🔑 Rules

### 1. Schema-First Development
- Always introspect schema before generating any code:
  ```bash
  supabase db pull --schema public
  supabase gen types typescript --local > src/types/database.types.ts
  ```
- Or with Prisma:
  ```bash
  npx prisma introspect
  npx prisma generate
  ```
- These types **must be imported everywhere** (UI, API, services).

---

### 2. Type Enforcement
- Never hardcode field names/types.  
- Always import from `src/types/database.types.ts`.  
- Example:
  ```ts
  import { Database } from "@/types/database.types";

  type User = Database["public"]["Tables"]["users"]["Row"];
  ```

---

### 3. API Contracts
- All API endpoints must use **Zod schemas** that mirror the DB.  
- **Pattern for every API route**:
  ```ts
  import { z } from "zod";
  import { db } from "@/lib/db";
  import { Database } from "@/types/database.types";

  const insertUserSchema = z.object({
    id: z.string().uuid().optional(),
    email: z.string().email(),
    created_at: z.string().datetime().optional(),
  });

  export async function createUser(payload: unknown) {
    const data = insertUserSchema.parse(payload);
    return db.from("users").insert(data).select("*").single();
  }
  ```
- No raw inserts without validation.

---

### 4. UUID Handling
- UUIDs are **never generated in UI**.  
- Backend must:
  - Use `crypto.randomUUID()` in Node.js, OR  
  - Let Postgres/Supabase defaults handle it (`uuid_generate_v4()`).  

---

### 5. UI Form Generation
- Forms must be scaffolded using **React Hook Form + Zod Resolver**.  
- Each form must map DB types → Zod → form controls.  
- Example:
  ```tsx
  import { useForm } from "react-hook-form";
  import { zodResolver } from "@hookform/resolvers/zod";
  import { z } from "zod";

  const schema = z.object({
    email: z.string().email(),
    age: z.number().int().min(18),
  });

  export function UserForm({ onSubmit }) {
    const { register, handleSubmit, formState } = useForm({
      resolver: zodResolver(schema),
    });

    return (
      <form onSubmit={handleSubmit(onSubmit)}>
        <input {...register("email")} type="email" />
        <input {...register("age")} type="number" />
        <button type="submit">Save</button>
      </form>
    );
  }
  ```
- Required DB fields = required inputs.  
- Fields with defaults = optional inputs.  

---

### 6. Error Handling
- All errors must be explicit.  
- Invalid payloads must **throw a typed error**:
  ```ts
  try {
    await createUser(formData);
  } catch (err) {
    if (err instanceof ZodError) {
      return { error: "Validation failed", details: err.errors };
    }
    throw err;
  }
  ```

---

### 7. Data Normalization
- Dates → Always ISO UTC strings.  
- Enums → Must be dropdowns with DB enum values.  
- JSON fields → Must be `JSON.stringify`’d before insert.  
- Boolean fields → Always checkbox/toggle, default = `false`.  

---

### 8. Auto-Sync Workflow
Every generation run must:
1. Pull DB schema.  
2. Regenerate TypeScript types.  
3. Generate Zod validators.  
4. Scaffold/update forms with `react-hook-form`.  
5. Ensure API routes validate + sanitize before DB insert/update.  

---

## 🔮 Edge Case Enforcement
- **Invalid UUIDs**: never accepted, must fail validation.  
- **Missing attributes**: must be provided or filled by defaults.  
- **Extra attributes**: stripped before DB insert.  
- **Foreign keys**: enforce via dropdowns/relations in UI.  
- **Unique constraints**: enforce optimistic check before insert.  
- **Migrations**: If DB schema changes, regenerate all related code automatically.  

---

## ✅ Output Expectations
When Gemini generates:
- No DB mismatch errors (invalid UUIDs, missing attrs).  
- No runtime type errors.  
- No silent failures.  
- Schema changes propagate through **types → API → UI**.  

If Gemini cannot generate code that satisfies these rules → **fail loudly** with an explanation.
